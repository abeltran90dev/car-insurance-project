  2. Agents and skills

  Agents. Each file records the reasoning behind its split, its tools and its
  model.
  - spec-writer (opus; Read/Grep/Glob/Write): writes SPEC-US-XX.md with status:
    Draft and is never allowed to approve it. It turns story gaps into numbered
    GAP-NN items. It lists open questions and decisions that need an ADR
    separately.
  - architect (opus; plus WebFetch): writes ADR-NNN-*.md as Proposed, with at
    least three real alternatives. It checks framework facts against official
    docs and never edits an existing ADR; changes go in a new one.
  - implementer (sonnet): first checks the spec status. It replies REFUSED if
    the spec isn't Approved or an ADR it depends on isn't Accepted. It works on
    a branch per story with atomic commits and does fix runs per finding ID.
  - test-writer (sonnet): writes tests from the acceptance criteria, named with
    their AC IDs. It may only touch test files. When a test exposes a bug it
    keeps the test and reports the bug instead of weakening the test.
  - reviewer (opus; Read/Grep/Glob only): gets the diff and test summary in its
    prompt and returns a report that the main session saves. It never fills in
    the human-decision or resolution-commit columns.

  Skills:
  - spec-authoring: the full spec template and a gap checklist covering the 8
    categories you listed, plus a "Ready for HC1" self-check.
  - strapi5-content-modeling:

    - A REST query cheat sheet and idempotent seeding at startup.
